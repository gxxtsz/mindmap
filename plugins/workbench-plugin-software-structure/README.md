# 软件结构可视化

在个人工作台中打开 `.software-structure` 软件结构文件，浏览其中的模块依赖图。插件默认启用，可在「设置 → 插件管理」中调整，重启后生效。

## 下载模板并生成结构图

1. 从「文件 → 下载软件结构模板…」选择保存位置。打开软件结构文档后，也可点击标签栏右侧的下载图标。
2. 将下载的 `软件结构模板.software-structure` 与目标项目的源码、构建配置或架构说明一起交给 AI，请它按模板中 `template_instructions` 的指令生成软件结构数据。
3. 将 AI 生成的 JSON 对象保存为 UTF-8 编码的 `项目名.software-structure`，再通过「文件 → 打开」查看目标项目的模块依赖图。

## 打开和浏览

从「文件 → 打开」选择下载的模板即可查看示例依赖图，也可将 `.software-structure` 文件路径作为工作台的启动参数。

- 连线箭头由依赖方指向被依赖方。带警示色的虚线表示循环依赖，包含自依赖。
- 画布用完整依赖图从上往下分层，同层模块横向并列。算法参考 Graphviz `dot` 的分层方法，用最小费用流求解层级和层内坐标的加权跨度。等代价的节点优先放入更空的层，同层通过加权中位数和相邻交换减少交叉。跨层边沿虚拟节点走线，循环边按原始方向绘制。 [分层布局算法论文](https://graphviz.org/documentation/TSE93.pdf)
- 用右侧工具按钮或「视图 → 面板 → 连线筛选」打开侧栏。勾选模块后，它的卡片留在原位，连向它和从它发出的线及箭头都会隐藏，包括自依赖和循环依赖。连线的两端都未勾选时才显示。键盘选中列表项后按空格也可切换勾选。
- 点击侧栏标题栏的勾选图标可批量修改。提示「隐藏全部连线」时点击会勾选全部模块，提示「清除筛选」时点击会取消全部勾选。
- 每次修改立即保存到当前文件，并刷新该文件的各个标签。批量操作一次提交所有改动。保存失败时，侧栏恢复上次保存的勾选状态，状态栏和操作日志会显示原因。
- 左键点击模块卡片主体或标题选中模块，高亮它可见的直接入边和出边。点击画布空白处清除选中。
- 有可隐藏的连线时，状态栏右侧显示漏斗图标。高亮表示筛选生效，点击可在当前标签临时显示全部连线，再点一次恢复筛选。侧栏保存成功后，当前标签立即恢复筛选，其余标签各自保留预览状态。
- 按住右键拖动画布平移，滚动鼠标滚轮缩放。点击状态栏右侧的「适应窗口」查看全图。点击缩放百分比恢复到 100%，并在可平移范围内保留当前查看位置。
- 将鼠标停在模块上查看名称、ID 和说明。通过标签右键菜单的「复制标签」可以在独立视口中浏览同一文档。
- 模块目录和依赖关系以只读方式浏览。复制标签或恢复会话时，按文件中的筛选设置显示连线，读取有效的缩放和位置，并从未选中模块的状态开始浏览。若在外部编辑了文件，关闭该文件的全部标签后重新打开即可读取最新内容。

## 文件格式

文件扩展名为 `.software-structure`，内容使用 UTF-8 JSON，可带 BOM。以下文件表示「应用」依赖「核心」，筛选时隐藏与「核心」相连的线。

```json
{
  "schema_version": 1,
  "modules": [
    {"id": "app", "name": "应用"},
    {"id": "core", "name": "核心", "description": "提供业务基础能力"}
  ],
  "module_dependencies": [
    {"source": "app", "target": "core"}
  ],
  "hidden_edge_module_ids": ["core"]
}
```

| 顶层字段 | 类型与约束 |
| --- | --- |
| `schema_version` | 必填整数。当前支持 `1`。 |
| `modules` | 必填数组。每项为模块对象。空数组显示空图。 |
| `module_dependencies` | 可选数组。每项为依赖对象，省略时按空数组读取。 |
| `hidden_edge_module_ids` | 可选数组。每项是唯一且已声明的模块 ID。勾选按模块顺序保存，清除筛选时保存空数组。 |

- 模块对象的 `id` 和 `name` 是必填字符串，至少包含一个非空白字符。`id` 在整个文档中唯一，按原文匹配，区分大小写。`description` 为可选字符串。
- 缺省 `hidden_edge_module_ids` 时，打开旧文件会读取模块对象中为 `true` 的 `is_public_dependency` 作为初始勾选。首次保存筛选时同时写入新字段和删除模块上的旧标记，保留 BOM、换行和扩展字段原文。
- 依赖对象的 `source` 和 `target` 是必填字符串，分别引用依赖方和被依赖方的模块 ID。每组有序的 `source` 和 `target` 只能出现一次。允许孤立模块、双向依赖、自依赖和其他循环依赖。
- 同一软件结构文件可通过可选字段添加 API、软件架构等数据，并通过模块 ID 引用共享模块目录。版本 1 的读取器校验已识别字段，允许额外字段。不兼容的格式变更应递增 `schema_version`。
